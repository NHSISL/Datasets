## Summary

This release introduces several important updates to the platform, including enhanced schema support for governance configurations and significant refactoring of the person model to improve data access control and maintainability. Pipeline configurations have been updated to ensure deployments target the correct environment by default, and the EMIS_OLIDS revision has been advanced to align with the new release. Collectively, these changes streamline operations, strengthen data quality and governance, and improve the flexibility and reliability of deployment processes.

### New Features
- Add schema support for Governance YAML file, enabling masking control data to be formally defined and managed. *[PR: [#53](https://github.com/NHSISL/LondonDataservices.Transform.OLIDS_Enrichment/pull/53)]*
  > ✨ ***Feature:*** Users can now specify and enforce schema for governance-related configurations, improving data governance and compliance.

### Improvements
- Updates to NDOO and PDS pipeline configuration to default to the release environment and use tag selectors for dbt runs. *[PR: [#55](https://github.com/NHSISL/LondonDataservices.Transform.OLIDS_Enrichment/pull/55)]*
  > 🎯 ***Impact:*** Ensures that deployments are directed to the intended environment by default and makes dbt execution steps more maintainable and flexible.

- Update EMIS_OLIDS revision to v2.2.0EMIS. *[PR: [#56](https://github.com/NHSISL/LondonDataservices.Transform.OLIDS_Enrichment/pull/56)]*
  > 🎯 ***Impact:*** Aligns the EMIS_OLIDS release versioning with the latest changes, ensuring consistency across deployments.

### Refactoring
- Refactor Person model for view materialization and access policy updates, including simplification of logic, improved maintainability, and enhanced data quality checks. *[PR: [#54](https://github.com/NHSISL/LondonDataservices.Transform.OLIDS_Enrichment/pull/54)]*
  > ♻️ ***Refactor:*** Simplifies person versioning and entitlement logic, enforces row access policies more directly, and adds new data quality rules—making the models easier to maintain and ensuring correct data access control.
