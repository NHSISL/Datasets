## Summary

This release introduces significant enhancements to the EMIS OLIDS transformation models, including new supplier-facing request models for improved interoperability and support for downstream enrichment processes. Key improvements address data quality and consistency, such as preventing duplicate patient addresses and correcting organisation code mismatches. The release also includes important internal refactoring and cleanup, improving maintainability and aligning with updated platform architecture. No breaking changes are expected for downstream consumers, but some logic and macro migrations require parallel updates in related repositories.

### Dependency changes

- OLIDS_Share: [v1.2.0](../1_OLIDS_Share/v1.2.0.md) - ⬆️ upgrade

### New Features

- Add models for generating PDS and NDOO requests from EMIS Admin_Patient objects, enabling cross-supplier unioning and PDS trace requests. Documentation and uniqueness constraints are included for these new models. *[PR: [#98](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/98)]*
  > ✨ ***Feature:*** Enables downstream enrichment and improved interoperability by standardising request generation for patient data. Addresses known issue gap [#AB29779 KI-01: static PDS, UPRN and NDOO records](https://dev.azure.com/NELAnalytics/LondonDataService/_workitems/edit/29779)

### Improvements

- Add `distinct` to Patient Address output to prevent duplicate addresses from ingestion bugs, ensuring each address only appears once in the final data. *[PR: [#106](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/106)]*
  > 🎯 ***Impact:*** Improves data quality and reliability by eliminating duplicate patient addresses caused by source file duplication.

- Overwrite NEL practice with branch code in organisation tables to correct ODS Code mismatches, ensuring proper joins to other ODS data sources and enabling data sharing for affected practices. Updates all dependent models and tests. *[PR: [#107](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/107)]*
  > 🎯 ***Impact:*** Resolves data joining issues, supporting accurate data access and sharing for NEL practices.

- Update revision for OLIDS_Share dependency to v1.2.0. *[PR: [#108](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/108)]*
  > 🎯 ***Impact:*** Ensures compatibility and alignment with the latest version of shared platform dependencies.

### Refactoring

- Refactor and clean up EMIS OLIDS models and macros:
  - Remove legacy and unused macros (e.g., `generate_person_business_id`), transferring logic to OLIDS_Share.
  - Update documentation for person models and clarify EMIS-native record handling.
  - Remove PDS ingestion and person versioning logic, now handled in OLIDS_Enrichment.
  - Standardise naming conventions and address fields in models and tests.
  *[PR: [#98](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/98)]*  
  > ♻️ ***Refactor:*** Improves maintainability, reduces redundancy, and aligns logic with new platform architecture.
- Rename `PATIENT_FLAGGED_SENSITIVE` to `IS_PATIENT_FLAGGED_SENSITIVE` for clarity and consistency in naming conventions. *[PR: [#109](https://github.com/NHSISL/LondonDataservices.Transform.EMIS_OLIDS/pull/109)]*  
  > ♻️ ***Refactor:*** Enhances code readability and standardises field naming across models.
